QueueFlow

Queue and service desk system with instant updates across service stations, kiosks and public displays.

JavaSpring BootWebSocketReactPostgreSQL

The challenge

Synchronize ticket calls across screens without requiring reloads or mixing operator permissions.

The solution

Java/Spring Boot API, WebSocket communication with STOMP/SockJS and a React interface. Administrative, operational and public areas are separated.

Main features

  • Service counters, ticket issuance at kiosks and calls on attendant screens.
  • Administration dashboard with operational metrics and configuration.
  • Public display updated through WebSocket events.

Architecture

React and TypeScript frontend, Java 21 and Spring Boot backend, PostgreSQL persistence with Flyway, JWT authentication and WebSocket communication.

  1. React / kiosk / display
  2. REST + WebSocket
  3. Spring Boot
  4. PostgreSQL

Decisions and lessons learned

  • WebSocket events keep displays updated, while REST handles conventional workflows.
  • Distinct roles govern access to configuration, service operations and public pages.
  • Database migrations and end-to-end tests improve reproducibility.

Scope and limitations

The interface and API share the same origin. Kiosks and displays do not collect customers' personal data.

Documented evidence

  • Documented screenshots generated by the E2E suite
  • Flyway migrations and role-based authentication
  • Service operator demo account documented in the README
